## 确认的问题与修复

| 优先级 | 触发与影响 | 修复位置与行为 |
|---|---|---|
| P1 | 修改目标格式时，属性通知先于格式 ID 和引擎更新；同步保存会把旧格式写入队列，依赖判断也会读到不一致的路线。 | Models/MediaTask.cs：先同步更新完整路线，再发布通知。测试实际从通知回调保存并重载队列。 |
| P1 | 读取转换进度或错误管道失败时，编码进程仍继续执行；子进程继承输出管道后也可能阻止任务结束。 | Services/ConversionService.cs：提前处理取消、终止读取失败的进程，并在等待输出结束前清理子进程，限制管道收尾等待。 |
| P2 | 输出已成功提交后，日志刷新异常会覆盖成功结果，并跳过任务状态清理。 | Services/ConversionService.cs：隔离日志刷新错误，在 finally 中保证清理活动任务与取消记录。 |
| P2 | 运行或暂停时仍可修改输出格式、预设和音轨；异步转换的输出路径、编码参数和历史信息可能不一致。 | ViewModels/MediaTaskViewModel.cs、MainWindow.xaml：执行期间禁用选项，并在赋值入口拒绝修改；结束后恢复编辑。 |
| P2 | 任务选项事件直接等待保存且未处理异常，删除/取消操作也会丢弃保存任务；磁盘或权限错误可能导致崩溃或无提示保存失败。 | MainWindow.xaml.cs、MainWindow.Performance.cs：复用带异常处理的合并保存入口；日志不可写时仍显示保存错误。 |
| P2 | 监控目录仅检查文件长度稳定，会在复制暂停时导入半成品；复制超过十秒后则可能永久漏掉文件。 | Services/WatchFolderService.cs：等待写入句柄释放，检查长度和修改时间，保持可取消等待；删除文件后释放预留。 |
| P2 | PDF 稀疏文本页触发 OCR 后，空白或缺失的识别结果覆盖原有文字。 | Documents/PdfContentExtractor.cs：只有非空识别结果才替换原文。 |
| P2 | TXT 导出忽略表格单元格中的嵌套表格和脚注，造成内容丢失。 | Documents/PlainTextDocumentWriter.cs：递归展开嵌套内容，同时保留取消检查。 |
