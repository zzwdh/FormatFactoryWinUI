- 队列范围由 `Services/QueueActionPolicy.cs` 集中定义；清空待处理不再调用全局取消，停止只影响运行、暂停、分析和已调度的等待项。
- `Models/SettingsDraft.cs`、`Services/SettingsCommitCoordinator.cs` 与 `MainWindow.Settings.cs` 分离草稿、持久化和运行时应用。手动引擎路径检测先预览，保存后启用；较早保存完成不会清掉之后输入的改动。“已保存但部分服务应用失败”与存盘失败分开提示。
- `Controls/AdaptiveGrid.cs` 和 `MainWindow.Responsive.cs` 复用本地 WinUI；主任务列表保持有界高度，避免外层滚动使列表无限扩展。任务菜单保留原处理函数和任务标识。

- 所有新增流程文案纳入已有本地化资源，覆盖现有 15 种语言；未新增外部依赖、框架或素材。

## Windows 工具的目标结构

标题统一为“Windows 工具”，不再交替使用“原生能力 / 功能 / 工具”。主卡职责是进入任务和快速了解状态；详情窗口职责是定位能力问题。

- 卡片头：标题、简短用途、次要入口“系统能力详情”；“重新检查”作为次要动作。
- 默认摘要：总体可用/不可用/检测异常计数，加扫描仪、打印机与光盘设备计数；保留不可用与检测失败的区别，不把所有缺少可选组件都当作故障。
- 常用任务：扫描、打印、制作 ISO 保留直接入口；不将所有任务隐藏到诊断窗口。是否继续突出刻录，应根据实际使用频率验证。
- 低频操作：挂载/卸载 ISO、弹出光盘和打开系统设置归组；“擦除光盘”与常规动作分隔，执行前说明对象与后果。
- 异常处理：仅在与任务相关时显示原因和下一步。例：“未检测到扫描仪。连接设备后重新检查。”不能仅凭系统缺少某扩展就断言整个应用无法转换，需结合 FFmpeg 等现有路由。
- 详情窗口：默认折叠技术说明；已增加“仅看异常”和定位具体项目。保留已有的诊断复制功能与完整内容，不随主界面精简而丢失诊断价值。

文案规则：先讲发生了什么，再给必要的下一步。正常状态不反复提示；不删除有实际后果的提醒，不将不确定的能力写成确定承诺。

## 布局与视觉实施约束

断点按有效像素和内容可用空间设计，不把物理截图像素当作布局单位。当前默认实现窄于 720、720—1039、1040 及以上三档；设置卡内部使用 640 的窄屏阈值，详情窗口头部在 760 以下重排。阈值按各容器可用宽度计算，仍需长文案和控件最小可用宽度实测；这些不是已验证的产品尺寸限制。

基于本地项目现有的 WinUI/XAML 技术栈实现自适应网格；顶栏随宽度重排，任务参数从横排切为分行，设置卡标题与控件上下排列。已使用当前项目的本地 SDK 编译验证，尚待真实窗口实测；未引入外部 UI 框架或素材。

复用现有 WinUI 主题资源，补齐语义样式：主/次文本、卡片、强调/错误/警告状态；间距采用 4/8/12/16/24/32 的有限集合。优先统一控件高度、标题层级和焦点描边，再增加动效。减少动画、高对比度、文本缩放都纳入验收，不只检查浅色主题。

复用本地已存在的动作本地化资源，为无文字按钮设置 `AutomationProperties.Name`，与现有工具提示保持一致；表单名称与可见标签一致。用本机键盘和读屏结果验收，不以属性存在代替实际可用性。
