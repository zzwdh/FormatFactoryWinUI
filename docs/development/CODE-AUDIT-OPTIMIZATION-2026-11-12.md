# 代码审计与优化交付

范围：用户批准的 8 项审计条目。以当前工作区为基线，保留此前所有未提交改动；不改变版本号、包身份，不打包、不安装、不发布。

## 实现范围

1. **原生图片与光盘成品恢复**：验证后的提交使用 `CommitValidated`；提交失败返回恢复编号或保留路径。恢复索引不可写时，原始私有成品继续保留，不能被常规清理删除。
2. **图片中转隔离与完成进度**：PNG 中转固定写入私有目录，不继承对外输出分组；内层编码进度最多映射到 95%，最终发布完成后才报告 100%。
3. **自动化归档事务**：移动前持久化目的地及内容身份；移动成功后的提交不受普通停止取消影响；启动恢复核对归档内容，保留旧记录兼容。
4. **任务栏进度刷新**：输出存在性在后台探测，宿主线程只读取缓存；以任务身份、路径及代次拒绝过期结果，关闭时停止等待。
5. **自动化历史与存储**：历史查询建立索引，保留全部历史版本去重；减少重复解析和无变化检查点的写入，并识别外部文件变化。
6. **旧数据迁移**：首次完整复制成功后写入带来源身份的完成标记；后续启动不枚举旧目录。失败不写标记，私有临时文件复制后原子发布，不覆盖现有数据。
7. **日志管理**：应用、任务及外部进程日志按 8 MiB 分段轮转，保留 2 份备份；后台每 5 分钟至多检查一次，按 30 天和 256 MiB 目录软预算清理非活动日志。保护当前应用日志、活动任务、开放文件、未知文件及非日志数据；活动数据占用超过预算时不强行删除。
8. **PDF 密码框复用**：用真实 WinUI 队列模板验证同一已加载控件更换任务时的密码状态，修复任务身份同步并验证字典不交叉修改。

## 边界

- 性能基准使用隔离的合成数据，不能代表所有用户机器、网络盘或大目录的实际耗时。
- 系统文件存在性查询一旦进入离线网络盘访问，无法由托管取消强制中止；它必须留在有界后台工作中，且关闭后不得访问窗口。
- 首次旧数据迁移仍需完成实际复制后才能读取目标数据；完成标记只优化后续启动。
- 新归档意图的内容校验会读取来源数据，换取中断恢复时的正确归属。
- 物理光盘、ARM64 真机及 Microsoft Store 安装/发布验收不包含在本次本机代码验证中。
- 构建使用 `work/NuGet.Offline.Config` 及现有依赖缓存；未执行在线 NuGet 漏洞审计。
