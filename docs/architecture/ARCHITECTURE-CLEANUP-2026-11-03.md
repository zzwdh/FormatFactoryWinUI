# 首轮架构整理（2026-11-03）

本轮在既有 Core / Engine / Presentation / Windows Host 分层内抽离压缩包任务会话和共享策略。目的是让执行、退出恢复与保存故障可以脱离真实窗口验证，并减少普通转换对自动化编排的依赖。

## 可追溯基线

工作开始时保存了 617 个源文件、项目文件和相关构建输入，记录逐文件 SHA256、HEAD、工作区状态及既有 tracked diff，位于 `work/architecture-cleanup-20261103/baseline`。既有大量未提交功能得到保留，本轮不能仅用 HEAD 代表整理前内容。

- 完整托管基线：2,156 项，2,131 通过、25 失败、0 跳过。
- 压缩包真实界面基线：8/8 通过。
- 完整真实界面基线：149/149 通过，包含退出恢复及已发布产物收据恢复。

首轮托管试运行曾选中系统 WinGet 的不可启动 FFmpeg 链接，导致 80 项失败；其日志保留。正式对比基线和整理后测试都使用 `FORMAT_FACTORY_TEST_ENGINE_DIRECTORY=work/ffmpeg-pruning/baseline-runtime`，引擎身份与 25 项既有失败记录在 `baseline/known-failures.json`。这不是对生产引擎发现规则的修改。

## 责任划分

| 归属 | 类型 | 责任 |
| --- | --- | --- |
| Core | ArchiveTask | 任务身份、选项、进度、结果和检查点；密码只在内存选项中 |
| Core | ArchiveAbstractions | 转换、任务保存和提交收据的最小接口 |
| Engine | ArchiveSession | 执行、恢复、单项/整批取消、退出保留、串行检查点、历史补录 |
| Presentation | ArchiveTaskItem | 包装同一任务模型，提供本地化、按钮状态、结果摘要和属性通知 |
| Windows Host | ArchiveConversionView | 文件选择、参数和密码对话框、打开结果位置、只读展示集合适配 |
| Engine | FileFingerprintService / ConversionFailurePolicy | 供转换、队列和自动化共用的指纹读取、临时失败分类 |

页面不再持有执行器、任务存储、提交收据、批次取消源或延时保存任务。展示项没有单独复制任务状态；来源、身份及结果仍由同一个 Core 模型提供。保留展示类型命名空间，避免修改既有绑定名称。

自动化原有静态工具方法已移除，生产与测试调用均转到共享策略。指纹模型和序列化字段、可重试 IO 错误集合、转换参数及文件格式没有迁移。

## 行为约束

1. 首次恢复成功之前不接收新任务、不开始转换、不保存。损坏或未来版本记录不能被空任务文件覆盖。
2. 在串行写锁内部捕获最新快照，防止排队的旧保存请求覆盖已完成任务。
3. 已验证产物发布后，只有成功检查点保存完成才能删除提交收据。保存失败保留产物及收据；历史写入失败保留成功状态并在下次恢复补录。
4. 用户取消保持 Cancelled；应用退出打断的待执行、运行及等待密码任务恢复 Waiting，等待用户继续。单项取消继续处理后续项。
5. 密码不进入检查点、历史和提交收据；完成、取消及释放时清除内存密码，同时保留加密意图。恢复后重新输入输出密码。
6. 密码回调通过宿主调度器运行；取消后的回调不能恢复 Running。进度同时检查批次代次和单项取消状态，上一轮回调不能更新重试后的任务。
7. 会话操作、集合及属性通知服从宿主同步上下文，后台只执行转换与来源测量。
