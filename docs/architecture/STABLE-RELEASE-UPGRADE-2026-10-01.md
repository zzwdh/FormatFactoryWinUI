# 稳定发布升级记录

实施与本机验证跨 2026-10-01 至 2026-10-02。

本轮以普通用户的日常批量转换和稳定发布为目标，冻结格式与系统能力扩张。重构前完整有效源码已保存为提交 `f277109`；工作缓存、测试结果和发布产物不进入源码基线。实现分支为 `codex/stable-release-upgrade`，最终实现与下述验证结果一起提交。

## 队列与退出

`FormatFactory.Engine/Application/QueueSession.cs` 负责可脱离窗口执行的恢复、调度、暂停、取消、检查点、历史及退出。窗口处理动作与展示，存储、导入、转换、历史、诊断和调度上下文可注入。

- 队列 v3 保存稳定任务 ID、状态、失败／阻塞原因、输入顺序和参数。兼容旧数组与 v2；密码不会持久化。
- 所有已保存任务先发布为可保留的占位记录，再探测源文件。离线或探测失败保留记录，显示原因，供手动重试或删除。
- 运行中和探测中记录恢复为待处理；暂停保持暂停，失败／取消保持原状态。启动不自动执行转换。
- 损坏队列在进程间锁内保留原字节的隔离副本，并尝试恢复检查点。未来版本和读取故障禁止覆盖。
- 退出先记录正在执行任务的保留意图，再取消并排空执行与附属回调。保存失败提供“保持打开”和“不保存并退出”；保持打开恢复任务接收能力。
- 转换成功、队列保存、历史、日志及通知分别处理。附属故障不会将已经提交的输出改成失败；历史失败保留单独提示。
- 恢复读取与 UI 发布之间关闭、关闭期间迟到导入、恢复尾项手动完成以及恢复探测中退出，都有独立时序测试。

## 无损承诺

GIF→动画 WebP 解析真实输入，并在输出提交前核对尺寸、帧数、逐帧时长和循环次数；无损模式还检查各帧 VP8L。当前不能兑现的动画输入／目标明确拒绝，包括动画 WebP、APNG、动画 AVIF、小于 20ms 的 GIF 帧以及超出目标循环字段容量的输入。

动画输出还核对 VP8L／VP8 位流头、尺寸和版本，并逐帧实际解码；合法头下的损坏帧也会拒绝。验证复用一个临时文件和 64KiB 复制缓冲，支持用户取消、30 秒单帧及 5 分钟整体上限，验证结束清理临时文件。

静态 FFmpeg 无损路线重新探测实际源精度，并比较源和输出的 RGBA64 解码像素 SHA256。未知默认编码器、缩放 ICO、抽帧、静态图像转视频以及已知位深下降不会标为无损成功。TIFF／BigTIFF 从实际 IFD 链核对页数，异常目录链和多页单帧路线拒绝。

原生图像路线保留现有暂存提交与色彩策略；无损转换必须验证像素精度、页数和尺寸。无法兑现时失败并说明原因，不能降为单页 FFmpeg 输出。

文档、电子书与多图到 PDF 的现有引擎无法证明完整保留页面、版式和图像精度，因此明确拒绝“无损”模式，包括重新构建 PDF 的 PDF→PDF 路线。普通质量、平衡、快速与固定版式功能保留。

Word 自动化在打开文档前设置 `AutomationSecurity = 3`。硬件编码预检允许调用方取消等待，共享探测和缓存继续供其他任务使用，取消的任务及时释放队列槽。

转换模式在模型入口统一大小写和空白。现有视频编码器与帧导出路线不能兑现无损承诺，明确拒绝对应无损请求；普通模式与视频容器的流复制仍保留。

## 入口与兼容

媒体、图片和文档保持主要入口。“高级工具”承载光盘、扫描、打印、原生能力摘要及详情；控件复用原有事件与同一设置草稿。格式 ID、文件关联、协议、COM 标识及应用数据路径保持兼容；App Service 同时接受 `get-state` 和既有 `status`。

Explorer 快速状态查询不访问选择提供器；没有可用缓存时返回 `E_PENDING`，允许慢查询时才分类。根菜单与子命令共享有期限缓存。任务列表过滤保留行身份；缺失键不再反复扫描剩余列表，并将屏外缓存固定为半个视口以控制卡片创建。缓存取舍依据 [微软 ItemsStackPanel.CacheLength 文档](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.controls.itemsstackpanel.cachelength)。

## 发布门禁

固定 MSVC、Windows SDK、MakeAppx、SignTool 和 .NET SDK；miniz 源码与许可在构建前校验锁定 SHA256。

发布分为候选构建和正式提升。候选生成双架构 MSIX、Bundle 和源码／工具／包哈希清单。正式提升复用已验收的完全相同字节，要求干净源码提交、业务回归、界面冒烟、真实启动三场景、九次性能采样、转换语料，以及 x64／ARM64 干净设备的安装、升级、核心转换和 Explorer 证据。x64 Office 测试基线还必须证明真实 DOC 宏未执行。没有证据不能生成正式上传包；ARM64 交叉编译只标记为构建证据。

操作说明见 [发布验收流程](../../packaging/RELEASE-ACCEPTANCE.md)。记录器只收集实际执行的证据，不代替安装或将未执行检查标成通过。

保留 .NET 11；当前锁定 RC1 的发布支持期限按上海日期为 2026-10-13。期限过后拒绝正式发布，需更新到仍受支持的版本并回归。[官方支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。

## 验证边界

本机验证包括托管回归、真实图片语料、WinUI 窗口、生产启动／恢复链、原生 x64 测试、ARM64 交叉构建、发布门禁拒绝案例与仓库校验。性能沿用超过 10% 停止发布的标准；原失败采样保留在工作目录，不通过修改阈值消除失败。

启动测试分别保存 0、100、1,000 项任务，包含不可用源及失败／取消／暂停状态，记录首次可交互、激活就绪、首条恢复和全部恢复四阶段。DOCX 后缀测试文件只用于启动导入元数据，文档转换质量另由真实 DOCX 语料验证。

尚未执行干净设备的 x64／ARM64 安装升级及 Explorer 验收、ARM64 真机转换、真实 Office 宏执行验证。没有生成正式上传包；这些证据缺失时发布门禁保持关闭。
