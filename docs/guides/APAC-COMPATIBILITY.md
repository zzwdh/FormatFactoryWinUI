# APAC 文件的兼容立体声音轨

本地源码已加入显式的“使用兼容立体声音轨（AAC）”选项。尚未重新打包或发布，现有安装包不会自动获得此功能。

## 使用方式

1. 导入同时含 Apple APAC 空间音频和普通 AAC 双声道音轨的视频或音频文件。
2. 选择视频或音频输出格式，以及普通转换模式。
3. 在任务行勾选“使用兼容立体声音轨（AAC）”，再开始转换。

该选项默认关闭。启用后只使用文件中第一条普通 AAC 双声道音轨，输出按所选目标格式编码；视频输出继续保留视频。界面会明确提示：APAC 空间音频和其他音轨不包含在输出中。原文件保持不变。

这为含兼容音轨的文件提供转换办法，没有新增 Windows 原生 APAC 解码器。只有 APAC、没有 AAC 双声道音轨的文件仍需可用的真实 APAC 解码器；不会为不支持的 APAC 生成替代静音音轨，也不会因兼容选项绕过 AAC 解码失败检查。无损模式禁止启用此选项，已启用时切到无损模式会阻止开始，可取消勾选后继续选择。

## 行为与验证

- 选择保存在队列和历史参数中；语言切换、重新打开队列和历史重建保持选择。修改界面不会改动已捕获的转换请求，运行中不可编辑。
- 预检查、短样本解码、兼容引擎准备与正式转换使用同一条 AAC 来源流。兼容准备只生成一条立体声 PCM 中间音轨，完成后恢复原输入、探测信息及选项。
- 输出检查要求一条非 APAC 双声道音轨，并检查视频/音频目标的媒体类型。图片和视频帧输出不使用音轨策略，保留原有无音轨输出行为。
- 44 种语言覆盖选项、遗漏音轨警告、缺失兼容音轨和无损模式提示。
- 真实 FFmpeg 转换测试使用合成的双 AAC 音轨文件，将未选流的探测元数据标为 APAC 来验证选择与隔离；另验证兼容引擎到 PCM 再到最终输出。没有把这些测试宣称为真实 APAC 解码成功。
- 2026-10-10 含当天全部最终源码的完整引擎/模型回归 1,320 项通过；真实 WinUI 68 项通过，Windows x64/XAML 构建 0 警告、0 错误。界面行在不占用焦点的隔离窗口中实际加载，验证默认关闭、语言切换、队列自动保存、开始门禁及原文件字节保留。

回归记录保存在本地 `work/sentry-validation/` 和 `work/ui-regression/`。

## APAC 解码

[Apple 官方 APAC 说明](https://developer.apple.com/av-foundation/Apple-Positional-Audio-Codec.pdf)描述其空间音频与平台解码能力；真实空间声场转换仍需要平台解码器及可分享样本验收。
