# 转换摘要、命名预览与批量队列优化

## 使用方式

- 转换成功后，任务行和历史记录显示输入大小、输出大小、增减比例和转换耗时。队列上方显示成功、失败、取消数量与可计算的体积汇总；批次完成通知使用本轮任务的结果。
- 同一来源的多种输出只计一次输入大小。输出组尚未全部成功、旧记录缺少统计、文件不可读取时，不显示推算的节省比例。Markdown 引擎尚未返回完整资源清单时，输出大小显示为未知。
- 打开队列的“输出设置”，选择常用模板或插入 `{name}`、`{format}`、`{date}`、`{preset}`、`{width}`、`{height}`。宽高取源文件尺寸；不可用时使用 `unknown`。预设字段优先使用多输出标签，否则使用质量模式。
- 编辑模板或切换保留目录结构时，下面会更新输出路径。优先预览选中任务及同组最多三份输出，没有任务时显示示例。预览处理已有文件和同组重名，不创建文件夹、不占用输出路径；实际转换时再次检查重名。
- 文件夹扫描和导入显示进度并可取消。已进入队列的批次保留，尚未发布的批次释放占用，可再次导入。文件夹扫描后按自然顺序分析；纯图片集合继续保留合并为一个任务的行为。

## 实现边界

- 队列使用任务 ID 索引，稳定保留原任务对象和顺序。批量接入和筛选时合并分组刷新，分组查询使用字典，减少重复遍历。
- 导入每批最多八项，沿用最多两个并行探测，等待界面接收后再处理下一批。关闭应用先取消并等待导入结束，再保存队列。
- 恢复记录的元数据在后台初始化索引，队列逐项查询只读取内存。过期文件清理独立执行；大文件复制在元数据锁外进行，并用单条记录的占用保护避免与清理冲突。
- 统计在后台测量已提交产物，不把缺失数据当作零。历史和保留的队列记录保存统计，重试和恢复旧结果不会显示过期统计。
- 路径预览延迟 180 毫秒合并连续输入，并在后台执行。它使用输出占用快照，不在全局输出锁内读取文件系统。

## 验证入口

- `FormatFactoryWinUI.Tests`：命名与冲突、统计持久化及未知值、索引一致性、渐进导入取消、恢复索引与并发清理。
- `tests/WinUiSmoke/Run.ps1 -Capture`：实际窗口导入及中途取消、摘要渲染与历史行复用、模板实时更新和本地化。
- `tests/WinUiSmoke/Run.ps1 -Performance`：九个独立进程的千项／万项筛选与真实窗口批量接入，区分等待和失败任务，并覆盖普通任务与真实多输出混排的万项队列。
- `tests/WinUiSmoke/Run.ps1 -Startup`：分别恢复 0、100、1,000 个已保存任务，检查不可访问来源与失败、取消、暂停状态保留，不自动开始转换。
- `tests/WinUiSmoke/Measure-Startup.ps1`：通过真实应用启动路径激活可见窗口，分别测量窗口首帧、可添加文件、普通及归档任务恢复完成；每档默认三个独立进程，保存原始计时、阶段重叠信息与源码指纹。旧的 `first-interactive` 仅表示设置应用完成，不能作为“可添加文件”的指标。
- `ResourceLifecycleRegressionTests`：重复创建／停止目录监听，启动／取消转换子进程，记录句柄及内存。设置 `FORMAT_FACTORY_STRESS_CYCLES=100` 可执行一百轮；这不等同于数小时持续运行认证。
