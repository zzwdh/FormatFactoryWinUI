# 任务恢复、错误处理与负载调度

## 压缩包任务

压缩包页面保留独立的批量列表。任务的来源、目标格式、校验方式和输出加密开关会保存；重新打开应用后恢复列表，由用户手动开始。上次运行中或等待密码的任务不会自动执行。

源包密码和输出密码不写入恢复文件或转换历史。恢复加密输出任务时必须重新提供输出密码，不会因密码没有保存而改为未加密输出。源包仍按需请求密码。

完成的压缩包结果进入统一转换历史，保留体积和耗时，并在压缩包页面显示完成汇总。历史中的“再次加入队列”返回压缩包页面，沿用格式、严格校验和加密开关；加密密码重新输入。重复写入同一结果不会产生重复历史。

取消或退出会等待当前转换停止并清理临时文件，已完成的结果保留。恢复文件损坏、来自不支持的新版本或无法保存时显示错误，不能把未知记录静默覆盖为空队列。

正常退出时尚未完成的任务保存为等待，用户主动取消的任务保持取消。若进程在成品发布后、成功状态保存前中断，恢复时通过提交回执核对文件长度、创建时间及 SHA-256，只认领已发布且配置一致的成品，避免重复转换；不会移动残留临时文件或替换已有文件。

## 失败后的处理

失败任务保留原始原因，并在能够确定原因时提供对应操作。输出写入或磁盘空间问题可以更换当前任务的输出目录；体积限制或参数问题可以打开转换设置；缺失来源和已校验的待恢复结果沿用现有恢复入口。无法可靠分类的错误继续显示详情和既有重试操作。

更换输出目录只影响选中的任务，不改变应用默认输出目录或其他任务。取消选择、关闭设置或未解决的配置问题不会自动开始转换。按钮在任务开始、完成或错误原因改变后重新计算，避免显示过期建议。

## 按负载调节并发

设置中的并行数仍是上限，电池和省电模式仍会进一步限制并行数。调度器结合任务分辨率、编码方式、页面数量等信息估算负载，并参考当前可用内存，决定何时接纳下一个等待任务。

资源紧张时仅延后新任务，不中断已经运行的任务；空闲队列至少接纳一个任务，避免较大的任务一直等待。手动顺序和优先级继续有效，任务不会为绕过负载限制而被自动重排。资源信息读取失败时采用保守的负载估算，仍可继续处理任务。

这项策略用于降低同时运行多个重任务造成的资源争用，不代表能够保证任何文件都不会遇到资源不足。

## 验证入口

- 托管测试覆盖压缩包状态保存和损坏保护、密码不落盘、历史参数往返、错误动作分类、输出目录隔离，以及负载接纳、取消、顺序和资源采样失败。
- WinUI 检查加载真实任务模板，验证恢复列表、加密重输、批次汇总、历史重放及错误按钮的可见性和动作。
- 实际压缩转换继续使用随包版本的 7-Zip，通过既有压缩包语料验证。
