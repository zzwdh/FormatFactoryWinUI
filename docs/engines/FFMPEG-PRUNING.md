# FFmpeg 兼容解码运行时裁剪

主 FFmpeg 继续使用锁定的 BtbN GPL shared 构建，提供应用的最终编码、硬件检测、HDR、图片及音视频处理功能。它与兼容解码器分别准备；主引擎的七个共享 DLL 都有实际导入依赖，不能直接删除其中的文件。

本轮按实际调用路线重新编译 LibreMPEG 兼容解码器。其源码提交仍为 `9c00336e26e45ed1274c9693382b1b1441ccaf6a`，对应源码包来自原发布者并锁定 SHA256。裁剪配置、依赖和构建入口位于 [packaging/ffmpeg](../../packaging/ffmpeg/README.md)。当前版本以根目录 `VERSION` 为准。

## 保留与移除

兼容引擎承担输入探测、短样本解码验证，以及生成 FFV1/PCM Matroska 中间文件。最终格式仍由主 FFmpeg 编码。兼容配置保留：

- 基线的文件解封装器、封装器、解析器、位流过滤器及可解码类型；BVC2、AC-4、Blackmagic RAW、Bink 2 单独检查。
- `ffv1`、`pcm_s32le` 两个中间编码器，以及空输出解码验证所需的 `wrapped_avframe`、`pcm_s16le`。
- 格式、采样、布局、旋转和透明度转换所需的基础滤镜。LibreMPEG 还会隐式插入 `asf2sf`、`acl2cl`、`ardftsrc`、`premultiply_dynamic`，不能仅按命令中出现的滤镜名裁剪。
- 软件 AV1/JPEG XL 解码、ICC 色彩、zlib/BZip2 压缩和 iconv 字符转换。主解码器名称列表不能体现所有容器内部压缩能力，因此另测压缩 Matroska 等实际输入。
- 字幕、附件、章节、元数据及多音轨流的现有中间文件传递方式。

兼容配置移除最终编码用的 x264/x265、替代 AV1 编码器等库、未调用的特效滤镜，以及采集/播放设备与硬件包装器。允许移除的输入设备名称严格限定为 `dshow`、`gdigrab`、`lavfi`、`vfwcap`。主引擎的 `lavfi` 仍服务于产品内硬件测试；主引擎的硬件编解码和用户输出能力不在此轮裁剪范围内。

两项程序共用六个私有 FFmpeg DLL，另带必要的 Microsoft 签名 VC 运行库。开发源码、编译器辅助工具、头文件、静态库和测试程序不进入 MSIX。所有组件的许可文本保存在运行时的 `licenses/`。

## 构建与校验

`prepare-engines.ps1` 的兼容引擎策略锁定的是对应源码归档，`archiveRole` 为 `corresponding-source`。准备过程先取得 CAJ 已有的隔离 Python，再调用源码构建脚本；没有为本地产物编造远程下载地址。

构建使用仓库锁定的 MSVC/Windows SDK 和固定版本的便携工具。NASM 的 Windows 路径限制通过 ASCII 临时构建目录处理。所有静态依赖与目标统一为 Release `/MD`。构建缓存按源码、配置、脚本和工具身份区分，复用时逐文件核对哈希。跨机器二进制完全一致尚未证明，实际构建输出始终通过准备收据和成品 MSIX 的逐文件 SHA256 绑定。

能力比较按可解码 codec ID 判断覆盖，硬件包装器或替代实现的名称差异单列；采集设备例外不会豁免文件格式。另有实际转换语料覆盖视频、音频、多音轨、透明图片、5.1 声道、字幕、附件、章节、Unicode 元数据、AV1、JPEG XL 与 BZip2 Matroska。新旧引擎的输出由固定的观察工具比较，且转换不能改写引擎文件。

这些语料不包含原始 BVC2、AC-4、BRAW、Bink 2 录制文件；其注册与源码保留检查不能替代所有真实文件的验收。ARM64 应用继续使用 x64 兼容运行时，原生 ARM64 真机验收另计。

未压缩运行时体积、ZIP 压缩字节和完整安装包体积分开统计。以本轮最终成品报告为准，不能把编译目录或源码缓存的大小当作安装占用，也不能把原型的体积当成已交付结果。
