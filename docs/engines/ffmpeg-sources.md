# FFmpeg 来源与运行时发现

FFmpeg/ffprobe 随 MSIX 提供。版本、下载地址和归档信息统一维护在 `packaging/engine-sources.json`，准备流程见 [打包说明](../../packaging/README.md)。旧的运行时下载器、下载源覆盖文件读取以及独立的 `ffmpeg-sources.json` 已移除，避免同一引擎维护两套版本来源。

主引擎使用 BtbN GPL shared 构建，`ffmpeg.exe`、`ffprobe.exe` 与七个私有共享 DLL 放在同一目录。两个工具共用编解码库；不携带 ffplay 或开发文件。x64、ARM64 的下载归档分别锁定 SHA256，所有共享 DLL 都列入必需文件及 PE 架构检查，并检查普通、延迟和间接导入，不能借用开发机 PATH 中的 DLL。

原锁定的 2026-09-19 每日构建已被上游清理，因此改用保留期更长的 2026-09-30 月末构建 `n9.0.2-17-g2a571b6068`。它来自同一 9.0 稳定分支，在 n9.0.2 后增加 17 个提交。升级验证应对照旧版编码器、解码器、滤镜、封装格式、协议和硬件加速清单，并执行实际编码与探测。

运行时 `FfmpegLocator` 保留用户指定路径、随包引擎、历史本地缓存与已安装工具的发现，以及 FFmpeg/ffprobe 可执行性检查；默认优先使用内置版本。用户仍可在设置页浏览路径或自动检测。内置组件缺失时会报告配置问题，不会自动联网下载。

兼容 LibreMPEG 使用 [转换专用源码构建](FFMPEG-PRUNING.md)：保留输入探测、广泛解码及 FFV1/PCM 中间文件生成，裁掉未使用的最终编码和特效依赖。源码包、便携构建工具、依赖版本及配置锁在 `packaging/ffmpeg/sources.lock.json`；运行时另有 `build-receipt.json` 记录实际输出哈希。主 FFmpeg 的上述完整输出配置保持原有职责。

旧用户数据目录中的引擎文件和配置不在本次源码清理范围内。MakeMKV 官方安装器的许可安装入口保持原样。
