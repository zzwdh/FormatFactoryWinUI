## 1. 交付内容

本项目是一款本地运行的 FFmpeg 图形化格式转换工具，界面风格参考格式工厂。当前版本已经完成音频、图片和视频的格式转换、混合任务队列、硬件加速、暂停继续、错误回退、任务恢复和安装包制作。

安装包信息：

- 默认安装位置：`%LOCALAPPDATA%\Programs\FormatFactoryWinUI`

- FFmpeg 不包含在安装包内，需要目标电脑已安装 FFmpeg 和 FFprobe

## 2. 当前功能范围

### 视频

支持输入和转换：MP4、MKV、AVI、FLV、MOV；支持读取单个 M4S 视频并转换为普通视频文件。

推荐模式会根据素材和输出容器选择 H.264 或 HEVC。HDR 输出到 MP4、MKV、MOV 时使用 10 位 HEVC；输出到 AVI 或 FLV 时转为普通 SDR。

### 音频

支持：MP3、WMA、M4A、FLAC、WAV、AAC。

从视频提取音频时，可以选择音轨序号。

### 图片

支持：JPG、PNG、ICO、BMP、WebP、AVIF。

ICO 会生成 16、24、32、48、64、128、256 像素的多尺寸图标。

### 任务能力

- 文件和文件夹拖放
- 音频、图片、视频混合任务队列
- 默认同时运行 2 个任务，可在设置中选择 1 到 3 个
- 单任务开始、暂停、继续、取消和重试
- 全部开始、全部暂停或继续、全部取消
- 真暂停 FFmpeg 进程，继续时从当前位置恢复
- 关闭应用后保存未完成队列，下次启动恢复
- 输出到自定义目录或源文件目录
- 自动处理同名文件
- 完成通知、提示音和系统托盘
- 每个任务保存独立日志

## 3. 针对本机硬件的优化

优化目标硬件：

- NVIDIA GeForce RTX 5060 Ti 16GB
- Intel Core Ultra 7 265K，20 核 20 线程

视频推荐模式的执行顺序：

1. NVIDIA NVDEC 解码并在显存内直接交给 NVENC 编码
2. NVIDIA NVENC 配合普通软件解码
3. Intel Quick Sync 硬件解码与编码
4. Intel Quick Sync 配合普通软件解码
5. CPU 编码

应用会通过一帧测试缓存 NVENC 和 Quick Sync 的实际可用性，避免每个任务重复尝试不可用的编码器。

NVENC 使用 P4 平衡预设，关闭高开销的完整多遍分析，保留空间自适应量化；Quick Sync 使用 Fast 预设和 8 帧异步深度。CPU 回退会根据并行任务数分配线程，避免两个任务同时占满全部 20 个逻辑处理器。

本机 20 秒、1920×1080、60 帧样片测试结果：

| 路径 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| NVIDIA NVENC | 4.10 秒 | 2.37 秒 | 约快 42% |
| Intel Quick Sync | 3.29 秒 | 3.00 秒 | 约快 9% |

结果来自合成样片，实际速度会随分辨率、编码格式、滤镜、磁盘和素材复杂度变化。

```text
FormatFactoryWinUI/
├─ src/
│  └─ FormatFactoryWinUI/

│     ├─ Models/                 设置、任务和媒体信息模型
│     ├─ Services/               FFmpeg 检测、分析、转换和队列服务
```

关键实现文件：

- `Services/PresetService.cs`：FFmpeg 参数、编码器预设和格式规则

- `Services/HardwareCapabilitiesService.cs`：NVENC 和 Quick Sync 可用性检测
- `Services/MediaProbeService.cs`：FFprobe 媒体分析、HDR 和音轨识别
- `Models/AppSettings.cs`：用户设置及默认并行数
- `FormatFactoryWinUI.csproj`：.NET、WinUI、自包含发布和 XBF/PRI 发布补全规则
- `installer/FormatFactoryWinUI.iss`：安装包配置

## 7. 构建和运行

以下命令均在项目根目录执行。

### 编译 Release

```powershell
dotnet build .\src\FormatFactoryWinUI\FormatFactoryWinUI.csproj -c Release -p:Platform=x64
```

编译结果位于：

```text
src/FormatFactoryWinUI/bin/x64/Release/net11.0-windows10.0.26100.0/win-x64/
```

### 自包含发布

```powershell
dotnet publish .\src\FormatFactoryWinUI\FormatFactoryWinUI.csproj `
  -c Release `
  -p:Platform=x64 `
  -r win-x64 `
  --self-contained true `
  -o .\work\publish
```

项目文件包含发布后处理规则，会把 `App.xbf`、`MainWindow.xbf`、`FormatFactoryWinUI.pri` 和图标源文件复制到发布目录。不要删除这条规则，否则发布版会在 WinUI 初始化阶段退出。

### 生成安装包

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" `
  ".\installer\FormatFactoryWinUI.iss"
```

生成结果位于：

```text
outputs/格式工厂WinUI-Setup-260824-x64.exe
```

如果 Inno Setup 安装在其他位置，请替换 `ISCC.exe` 路径。

## 8. FFmpeg 运行规则

- 推荐模式优先硬件编码
- 无损模式优先流复制；容器不兼容时任务会明确失败
- NVIDIA 和 Intel 编码失败后自动切换下一条路径
- HDR 到 MP4、MKV、MOV 时保留 10 位像素格式及可识别的色彩标记
- HDR 到 AVI、FLV 时使用软件色调映射输出 SDR
- MKV 尽量保留字幕和附件
- MP4、MOV 仅转换可兼容的文字字幕，图形字幕忽略
- M4S 自动生成时间戳；缺少初始化片段、编码参数或关键数据的 M4S 仍可能无法独立解析
- FFmpeg 使用较低日志输出并通过 `-progress pipe:1` 返回进度

## 10. 后续开发注意事项

1. 新增仅供后台使用的服务类时优先声明为 `internal`。公开服务类型可能被 WinUI 纳入 XAML 类型元数据，引发运行时解析错误。
2. 每次修改 WinUI 资源后，不仅要编译，还要实际启动 `work/publish/FormatFactoryWinUI.exe`。
3. 每次发布后确认以下文件存在：
   - `App.xbf`
   - `MainWindow.xbf`
   - `FormatFactoryWinUI.pri`
4. 修改硬件编码参数后，应分别验证 NVENC、Quick Sync、CPU 和 HDR 路径。
5. 版本号采用日期格式。下一次交付时同步更新项目版本、界面版本文字、安装脚本版本和安装包文件名。
