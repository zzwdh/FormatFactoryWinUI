# Bundled CAJ converter

`Prepare-CajEngine.ps1 -Destination <Engines/caj2pdf> -CacheDirectory <cache> -Architecture x64|arm64` creates a fully local engine. The destination must be a child of this repository's `work/` directory; junction destinations and archive links are rejected. `-Offline` prohibits downloads and verifies every cached archive. Each dependency is pinned by URL, version and SHA256 in `sources.lock.json`. Run `python.exe -I -B launcher.py --version` for a real dependency check, or `python.exe -I -B launcher.py convert INPUT -o OUTPUT` to convert.

The bundle contains embedded CPython 3.12.10, caj2pdf at revision 6c4bc32b15ce748d211f45d536f5d5511ef9f368, its x64 JBIG/JBIG2 DLLs, PyPDF2 2.2.0, imagesize 1.3.0, Pillow 11.3.0 and MuPDF's standalone mutool 1.26.2. Its private Microsoft-signed x64 Visual C++ runtime (`msvcp140.dll`, `vcruntime140.dll`, `vcruntime140_1.dll`) is extracted by `../vcredist/Prepare-VcRuntime.ps1` from the fixed archive in `../vcredist/sources.x64.lock.json` and placed beside mutool and Python. No separate Visual C++ installation is required. ARM64 packages use Windows x64 emulation for this engine because upstream ships x64 native decoding DLLs. No installed Python or PATH tools are used. Upstream DLL loading is patched to resolve relative to each module; all conversion scratch files go to a unique writable temporary directory. The launcher forces the absolute bundled mutool path, hides subprocess consoles, and suppresses Windows native dependency dialogs before probing so failures return a clear error.

Size reduction retains only mutool.exe from MuPDF (no viewers), only x64 CAJ native libraries, the embedded Python runtime without pythonw.exe, and the three required Python wheels. No pip, development headers, documentation bundle, test corpus, x86 engine, or general-purpose office components are installed.

CAJ, embedded PDF and KDH handling follow upstream. HN and C8 remain limited by upstream format support; pure-text HN and unknown variants may be rejected. Bundling the complete runtime does not imply that every proprietary CAJ/HN variant is supported. Failed conversions return nonzero and do not replace an existing output.

## Verification

Run `python.exe -I -B <repository>/packaging/caj/smoke-test.py --engine <Engines/caj2pdf>` for ten real tests: dependency discovery with an empty PATH, missing-component failures, explicit failures when each private Visual C++ DLL is removed, Unicode paths, PDF passthrough, an embedded-PDF CAJ container repaired through bundled mutool, concurrent conversions, unsupported-format failures that preserve output, HN image assembly, and no writes into the engine directory. Empty PATH does not remove the system DLL search path; the packaging checks must require the private runtime files and verify the native import closure independently. These synthetic regression fixtures do not claim coverage of all proprietary HN/C8 variants.
