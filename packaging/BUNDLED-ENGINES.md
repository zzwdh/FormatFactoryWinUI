# Bundled conversion engines

The application uses internal .NET/Windows implementations for PDF, EPUB, Markdown, images, OCR, ISO/CSO and native optical reads. The following third-party components are prepared by the locked build scripts. Hashes, versions, architectures and per-file payload checksums are recorded in `engine-sources.json`, each component's `sources.lock.json`, and `bundle-manifest.json`.

FFmpeg and LibreOffice use native x64/ARM64 builds. LibreOffice ARM64 receives native Microsoft Visual C++ runtime DLLs extracted from the signed ARM64 redistributable; the x64 DLLs in its MSI administrative System64 folder are excluded. The CAJ engine includes private x64 `msvcp140.dll`, `vcruntime140.dll` and `vcruntime140_1.dll` beside mutool and Python, extracted from the signed x64 redistributable for both application architectures. Its native helpers do not require users to install Visual C++ separately. The compatibility decoder, Calibre, CAJ and Cygwin optical fallbacks use the x64 Windows runtime (Windows x64 emulation on ARM64). MakeMKV is not silently installed or represented as an already available command-line engine. The user explicitly opens the original installer in Settings; Blu-ray availability depends on the installed product and its license.

FFmpeg's tools share seven private libav*/sw* DLLs instead of each embedding the codecs; ffplay and development files are excluded. The locked month-end FFmpeg 9.0 stable-branch build replaces the no-longer-retained September 19 daily build; it is 17 commits after n9.0.2, not the exact release tag. CAJ excludes unused Python executables and unused MuPDF utilities.

LibreOffice uses a headless conversion profile. It retains the native Writer/Calc/Draw/Math, chart, OLE, Basic/VBA and import/export libraries, private fonts, locale/layout resources and all languages' hyphenation dictionaries. In addition to help, galleries, templates, shell extensions, editing launchers, non-English UI translations, spell-check/thesaurus data and optional icon themes, the profile removes the separate Python runtime, Python/Java UNO components, preinstalled authoring scripts/wizards, AutoText/AutoCorrect resources, notebookbar definitions and the optional Python Lightproof grammar checker. Corresponding UNO factories and Lightproof extension registrations are removed with their implementations. Native JVM bridge DLLs imported by the shared conversion library remain. English is used only by the noninteractive backend; document language/layout and the application's translated interface are retained. Retaining Basic/VBA and OLE libraries preserves import/rendering support; it does not enable document macro execution.

Calibre uses a conversion profile for the application's EPUB-to-MOBI/AZW3 routes and ebook-meta validation. Other supported document/image inputs are normalized to EPUB by the application's own pipeline before Calibre runs. The complete frozen Python archive/index and conversion/metadata plugins remain, along with the required QtCore/Gui/Widgets/Network/Svg libraries, image codecs, fonts, ICU, language mappings, cover/jacket resources and hyphenation. The profile excludes GUI/server/device launchers, Qt WebEngine, QML/Quick, multimedia/private FFmpeg, speech engines, news recipes, reader/editor/server assets, CLI message translations and unused Qt bindings/plugins. ebook-convert, ebook-meta and the worker launcher remain. This is not a general-purpose Calibre installation: standalone Calibre PDF output and reader/editor/news/TTS features are outside this profile. The application's PDF conversion routes continue through its own pipeline or LibreOffice, as appropriate.

`LibreOfficePruning.ps1` and `CalibrePruning.ps1` apply explicit removal lists after MSI extraction. They reject reparse points and paths outside the runtime, require runtime anchors and preserve notices from removed subtrees in `pruning-notices/`. Preparation and package validation retain per-file hashes and check the remaining native dependency closure. Conversion comparisons cover text, page rendering and ebook content rather than requiring nondeterministic PDF/ebook bytes to match. The profile, validation scope and size-measurement rules are described in [OFFICE-EBOOK-PRUNING.md](../docs/engines/OFFICE-EBOOK-PRUNING.md).

License/copyright notices remain with every component. Distribution must also satisfy the respective GPL/AGPL corresponding-source obligations; the exact upstream source locations and build recipes are listed here and in component locks. The build cache includes matching Cygwin/cdrkit source archives. No claim of unrestricted redistribution rights is made for MakeMKV; only the unchanged free original installer is bundled according to its Windows license.

The compatibility runtime is built from the locked corresponding-source archive with a conversion-only profile. FFmpeg/ffprobe share six private libraries and app-local signed Microsoft VC runtime DLLs. Native input decoders, file formats, bitstream filters and input compression/character conversion support remain; unused final encoders, effect filters, capture devices and hardware wrappers are excluded. Four encoders provide FFV1/PCM intermediates and null preflight output. The regular bundled FFmpeg produces and validates the final user output. Software AV1/JPEG XL, ICC, zlib/BZip2 and iconv remain. The main and compatibility libraries stay in separate directories; matching DLL names do not make the different builds interchangeable. Source/tool locks, build receipts and per-file package hashes bind this locally built runtime to its inputs. See [FFMPEG-PRUNING.md](../docs/engines/FFMPEG-PRUNING.md) for validation scope. Original BVC2, AC-4, BRAW and Bink 2 recordings were not available for end-to-end corpus validation.
